# Requirements Catalog — scaleset-runner

scaleset-runner is a single Go Controller that registers one Scale Set per GitHub repository
and starts one ephemeral Runner Container per Job, using the
[`github.com/actions/scaleset`](https://github.com/actions/scaleset) client. One process serves
many repositories on a personal GitHub account (no organization) and shares a fixed number of
Slots across them. Terms are defined in [glossary.md](glossary.md).

**Out of scope for the first release:** organization- or enterprise-scoped Scale Sets,
autoscaling across more than one Host, VM-based isolation, a Slot limit or State Store shared
between several Controllers on one Host.

| ID      | Title                         | Requirement                                                                                                                                                                         | Category        | Priority | Status |
|---------|-------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------|----------|--------|
| NFR-001 | Default Slot limit            | The Controller's Slot limit defaults to 1 and is configurable from 1 to 32.                                                                                                              | Scalability     | High     | Open   |
| NFR-002 | Job start latency             | With a free Slot and the Runner Image already present, a Runner Container has written the Ready marker within 15 seconds of the start request arising. | Performance     | High     | Open   |

| NFR-010 | Scale Set count               | One Controller serves at least 20 Scale Sets concurrently.                                                                                                                         | Scalability     | Medium   | Open   |
| NFR-011 | Image size                    | The Controller image is at most 50 MB compressed.                                                                                                                                 | Portability     | Low      | Open   |
| NFR-012 | Idle runner removal           | A Runner Container whose Job was cancelled before it started is removed, with its Runner Registration, within 30 seconds of the Scale Set's assigned Job count dropping.            | Performance     | Medium   | Open   |

## Open Questions

| ID    | Question                                                                                                                                                       | Affects               |
|-------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------|
| Q-001 | Which GitHub App permissions does a repository-level Scale Set need? Tested 2026-11-13 with scaleset v0.5.0 and a `repo`-scoped OAuth token on a private personal-account repository: creating a Scale Set, opening a message session, generating a JIT Config, removing the runner, and deleting the Scale Set all work. Not yet tested with a GitHub App; deferred until FR-017 is built. | FR-017                |
| Q-002 | Does a fine-grained personal access token work, or only a classic one? The scaleset README only says "PAT". Test when FR-018 is built.                       | FR-018                |
| Q-003 | Does GitHub read the Capacity (`X-ScaleSetMaxCapacity`, set with the scaleset client's `SetMaxRunners`) as the total number of runners a Scale Set may have, or as the number of further Jobs it may take? Answered in part (2026-11-13): GitHub decides whether to assign a Job when it is queued. A Job queued while a Scale Set advertised 0 stayed queued on GitHub after later polls advertised 1. FR-009 therefore advertises the fixed Slot limit, as the scaleset listener and runscaler do with their fixed max-runners value. | FR-009, FR-010, NFR-003 |
| Q-004 | Does the Instance label on a Scale Set leave `runs-on: <scale set name>` matching unchanged? Test when FR-036 is built.                                     | FR-004, FR-036        |
| Q-005 | Does the GitHub Actions cache service restore the Docker images of a compose stack without delaying the Job start beyond a full pull, and does it hold all of them? Every Runner Container starts with an empty inner Docker daemon (NFR-006), so a compose stack restores all its images from the cache, which keeps 10 GB per repository by default. Measure a Job with Playwright and a database before relying on FR-025; a cache on the Host would be a new requirement. | FR-024, FR-025        |
